# 상식 퀴즈 게임 — Claude Code 구현 프롬프트

PRD(`prd.md`) 기반으로 3단계에 걸쳐 구현합니다.
각 단계 프롬프트를 Claude Code에 순서대로 입력하세요.

---

## STEP 1 — 프로젝트 골격 + 문제 데이터

```
상식 퀴즈 게임을 순수 HTML/CSS/JavaScript(프레임워크 없음)로 구현해 줘.
서버 없이 브라우저에서 바로 실행되는 단일 파일(index.html) 또는
index.html + style.css + script.js 구조로 만들어.

지금 이 단계에서는 다음만 구현해:

1. 파일 구조 생성
   - index.html (화면 골격)
   - style.css (기본 레이아웃)
   - data.js (문제 데이터)
   - app.js (게임 로직)

2. data.js — 문제 데이터
   아래 4개 카테고리, 각 10문제씩 총 40문제를 작성해.
   각 문제 객체 구조:
   {
     id: 1,
     category: "한국사",          // 한국사 | 과학 | 지리 | 일반상식
     question: "문제 텍스트",
     options: ["보기1", "보기2", "보기3", "보기4"],
     answer: 0                    // options 배열의 정답 인덱스 (0~3)
   }

   카테고리별 출제 범위:
   - 한국사: 삼국시대~현대사, 주요 인물, 사건, 문화재
   - 과학: 물리·화학·생물·지구과학 기초 상식
   - 지리: 한국 지리, 세계 지리, 수도, 지형
   - 일반상식: 문화, 스포츠, 언어, 예술

3. index.html — 화면 뼈대
   다음 6개 섹션을 div로 구성하고, 초기에는 메인 화면만 표시(나머지 hidden):
   - #screen-main       : 메인 화면
   - #screen-category   : 카테고리 선택 화면
   - #screen-quiz       : 퀴즈 진행 화면
   - #screen-feedback   : 정답/오답 피드백 화면
   - #screen-result     : 최종 결과 화면
   - #screen-ranking    : 랭킹 화면

구현이 끝나면 각 파일의 역할과 구조를 간략히 설명해 줘.
```

## STEP 2 — 게임 로직 구현

```
STEP 1에서 만든 파일 구조를 바탕으로 app.js의 게임 로직을 완성해 줘.

구현할 기능:

1. 화면 전환
   - showScreen(screenId) 함수로 #screen-* 간 전환
   - 현재 표시 중인 화면 외 나머지는 display:none 처리

2. 카테고리 선택
   - 4개 카테고리 중 하나 선택 → 해당 카테고리 10문제 로드
   - "전체 도전" 선택 시 40문제 랜덤 셔플 후 진행

3. 퀴즈 진행
   - 문제를 1개씩 순서대로 표시
   - 진행률 업데이트: "3 / 10" 형식
   - 현재 획득 점수 실시간 표시
   - 보기 4개 버튼 렌더링 (data.js의 options 배열 사용)

4. 정답 처리 및 즉시 피드백 (#screen-feedback)
   - 정답 선택 시:
     · 선택한 보기 버튼 → 초록색 강조
     · "정답입니다!" 메시지
     · 점수 +10점
   - 오답 선택 시:
     · 선택한 보기 버튼 → 빨간색 강조
     · 정답 보기 버튼 → 초록색 강조
     · "오답입니다. 정답은 [정답 텍스트]입니다." 메시지
   - [다음 문제] 버튼 클릭 → 다음 문제로 이동 (마지막 문제면 결과 화면으로)

5. 점수 계산
   - 정답: +10점 / 오답: 0점
   - 카테고리 만점: 100점 / 전체 만점: 400점

6. 결과 화면 (#screen-result)
   - 총점(예: 280 / 400)과 정답률(%) 표시
   - 등급 계산 및 표시:
     · 90% 이상 → S등급
     · 80~89%   → A등급
     · 70~79%   → B등급
     · 60~69%   → C등급
     · 59% 이하 → D등급
   - 카테고리별 점수 목록 표시
   - [다시 하기] 버튼 → 카테고리 선택 화면으로
   - [메인으로] 버튼 → 메인 화면으로

구현 후 게임 플로우(메인→카테고리→퀴즈→피드백→결과)가
정상 동작하는지 확인하고 버그가 있으면 바로 수정해 줘.
```

## STEP 3 — 랭킹 기능 + UI 완성 + 최종 점검

```
마지막 단계야. 랭킹 기능을 추가하고 UI를 완성한 뒤 전체를 점검해 줘.

1. 랭킹 기능 (localStorage)
   - 결과 화면에서 닉네임 입력 후 [랭킹 저장] 클릭 시 저장
   - 저장 데이터 구조:
     { nickname, score, accuracy, date }
     (accuracy: 정답률 %, date: "YYYY-MM-DD HH:mm" 형식)
   - localStorage 키: "quizRankings"
   - 랭킹은 점수 내림차순 정렬, 상위 10개만 유지
   - 동점자는 최신 기록이 아래로 (먼저 등록된 기록 우선)
   - #screen-ranking에 TOP 10 순위표 렌더링
     컬럼: 순위 | 닉네임 | 점수 | 정답률 | 날짜

2. UI 스타일 완성 (style.css)
   - 전체 배경: 부드러운 그라디언트 또는 단색 (밝고 캐주얼한 느낌)
   - 카테고리 선택: 카드형 레이아웃 (hover 효과 포함)
   - 보기 버튼: 클릭 전/정답/오답 상태별 색상 구분
     · 기본: 흰색 배경 + 테두리
     · 정답: #4CAF50 (초록)
     · 오답: #F44336 (빨강)
   - 등급 표시: 크고 굵게, 등급별 색상 차별화 (S=금색, A=은색, B=파랑 등)
   - 반응형: 모바일(max-width 480px) 기준으로 버튼 크기 및 여백 조정

3. 접근성
   - 키보드로 보기 선택 가능: 숫자키 1~4 → 보기 ①②③④ 선택
   - [다음 문제] 버튼 포커스 자동 이동

4. 최종 점검 체크리스트
   - [ ] 40문제 전부 출제되는지 확인
   - [ ] 전체 도전 시 랜덤 셔플 동작 확인
   - [ ] 정답/오답 피드백 색상 정상 표시
   - [ ] 랭킹 저장 및 정렬 정상 동작
   - [ ] 모바일 화면(480px)에서 레이아웃 깨짐 없음
   - [ ] 페이지 새로고침 후 랭킹 데이터 유지 확인

체크리스트 항목을 직접 확인하고, 문제가 있으면 수정 후 완료 보고해 줘.
```
